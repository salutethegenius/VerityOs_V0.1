# V0.1 threat model

V0.1 is a release-candidate / pilot system, not a certified government security product. This document extends [threat-model.md](./threat-model.md) with the full Shell–Core–Nova–connector surface.

## Assets

- Tenant identity (users, roles, permissions, sessions)
- Knowledge blobs and approved source versions
- Model Router decisions and prompts (not logged by default)
- Nova artifacts and social drafts
- Approvals and connector action records
- Audit ledger, Execution Graph V2, Verity Records
- Service credentials and connector secrets
- Backup sets (operational, not evidence)

## Actors

Honest operator, malicious org member, cross-tenant attacker, stolen-session browser, compromised model provider, compromised Meta-like connector, backup thief, curious analyst.

## Trust boundaries

| Boundary | Rule |
| --- | --- |
| Browser / Shell | Same-origin UI. No Nova/Core internals, no Postgres, no `NEXT_PUBLIC_` secrets. |
| Shell / Core | Cookie session + allowed Origin on unsafe methods. Shell forwards `x-request-id`. |
| Core / Nova | Bearer `NOVA_INTERNAL_TOKEN`. Nova is single-org per process. Core injects `actor_id` / `organization_id`. |
| Core / connector | Secrets stay in Core. Idempotency ledger is authoritative. Ambiguous Meta → `needs_review`, no blind retry. |
| Core / Postgres | All tenant rows carry `organization_id`. Composite FKs from Phase 3–6. |
| Core / Knowledge files | Paths under `VERITY_DATA_DIR/blobs/<org>/<version>`. Filename traversal rejected. |
| Offline verifier | Hash Format V2 + Graph V2. No chain-head signature. |

## Threats

| Threat | Current mitigation | Known limitation | Future mitigation |
| --- | --- | --- | --- |
| Cross-tenant access | Org-scoped queries, composite FKs, session org, tests | Platform `platform.cross_org` credentials are bootstrap authority | Reduce platform creds; per-tenant Nova |
| Credential theft | HttpOnly SameSite cookies, hashed session tokens, generic login errors, login throttling | In-process rate limits; no device binding | Token binding, lockouts with operator UX |
| Prompt / data exfiltration | Classification policy, local/mock default, logs redact secrets and do not dump prompts | Model provider compromise still leaks the prompt it receives | Local-only policy enforcement with signed routing |
| Malicious uploads | 10 MB cap, MIME sniff, DOCX zip limits, HTML strip, parser timeout, no OCR | Parser bugs remain a residual risk | Isolate parsers further |
| Approval bypass | Self-approval denied; Core decides; Shell hiding is not security | Skill `approval_required` still allows draft generation | Stronger pre-open checks where needed |
| Artifact substitution | Artifact hash on approval and connector | Client-side “unsealed edit” is blocked from publish | Hardware display of hash |
| Connector replay | Idempotency key + action ledger | Duplicate *attempts* may exist as `needs_review` | External provider receipts |
| Audit tampering | Append-only SQL, hash chain, Graph V2 | DB superuser can still rewrite disks | Signed heads, external anchor |
| Rollback / truncation | Backup hashes; verify detects in-bundle edits | **Unsigned chain heads: an older consistent restore still verifies** | Chain-head signing / anchoring (out of scope) |
| Provider compromise | Fail closed; no silent cloud fallback when policy forbids it | Operator can still misconfigure a cloud model | Sovereign profile + local routing only |
| Backup theft | Operator-controlled destination; no secrets in docs | Backup files are plaintext SQL + blobs | Encrypt backup sets at rest |

Session cookies: HttpOnly, SameSite=Lax, Secure when the HTTPS profile is on, 12h TTL. Logout deletes the hashed row. Origin allowlist is not a general CSRF framework.

CSP (Shell): `script-src` includes `'unsafe-inline'` (and `'unsafe-eval'` in Next.js development) so the App Router can boot. Documented exception. Core API uses `default-src 'none'`.
