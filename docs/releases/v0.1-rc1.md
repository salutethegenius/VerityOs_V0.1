# VerityOS V0.1.0-rc1

Pilot / release candidate. **Not** a certified government security product.

## Included

Identity, RBAC/Command, Knowledge, Model Router, Nova, Approvals, Connector Gateway (mock Meta), Shell, Audit Kernel V2, Execution Graph V2, offline evidence verification, configuration profiles, health/readiness, backup/restore scripts, synthetic government communications demo, security headers, conservative in-process rate limiting, request IDs, structured redacted logs, secret scan, dependency scan policy.

## Excluded (intentional)

Hummingbird image, TPM, chain-head signing/anchoring, SAML/OIDC, additional connectors, billing, mobile app, workflow builder, custom model training, Kubernetes, Redis, Kafka, large observability stacks, production Content-Loop cutover, production Slack/Meta credentials.

## Profiles

- **development** — mock model, mock embeddings, seeded test users, developer conveniences.
- **demo** — real Postgres, Shell, Core, Nova; mock or explicitly configured model; mock Meta by default; synthetic institutional data; no implied mock embeddings.
- **sovereign** — intended for private/local deploy; local/private model routing and embeddings; no required cloud dependency for core operation. **Hardware (Hummingbird) is untested in this candidate.**

## Known limitations

- Audit chain heads are unsigned/unanchored. Restoring an older consistent database still verifies internally.
- Rate limits are in-process (single Core process). Connector idempotency remains the duplicate-action control.
- Nova is single-organization per process.
- Shell CSP allows `'unsafe-inline'` (and `'unsafe-eval'` in Next development) so Next.js can boot.
- Mock Meta is not Facebook production.
- V0.1 does not claim Fact Verified or Truth Verified.

## Security posture

Fail-fast config, Origin allowlist, HttpOnly sessions, generic login errors, login/Nova/upload/approval/connector/verify rate limits, tenant isolation tests, Knowledge upload bounds, no secrets in system endpoints. See [v0.1-threat-model.md](../security/v0.1-threat-model.md).

## Deployment (clean environment)

```bash
cp .env.example .env
# fill profile, SESSION_SECRET, DATABASE_URL, CORS_ORIGIN, VERITY_DATA_DIR, embeddings
docker compose up -d postgres
pnpm install && pnpm db:migrate && pnpm build
VERITY_PROFILE=demo VERITY_DEMO_RESET=1 pnpm demo:reset
# start Core, Nova, Shell, meta-mock — see docs/deployment/development.md
pnpm demo:check
```

Compose demo stack: `VERITY_PROFILE=demo docker compose --profile demo up` after seed tokens are in the environment. No real customer credentials.

## Rollback

Restore the previous backup set onto a **fresh** Postgres and `VERITY_DATA_DIR`. Do not `db:migrate:down` in operations. Unsigned heads cannot prove you did not roll back.

## Open risks

Unsigned chain heads; single-process rate limits; parser residual risk; Nova one-org; operator mishandling of demo passwords; dependency advisories requiring triage.

Release gate: `pnpm release:check` (E2E/docker/live demo can be skipped with env flags in CI jobs that already cover those pieces).
